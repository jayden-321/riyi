# 日益 · iPhone 与 Apple Watch 试用源码

这是「日益」的 iPhone / Apple Watch 客户端源码，供朋友在自己的设备上试用。仓库包含客户端编译所需的动作指南数据；不包含后端源码、服务器配置、账号、签名证书或安装包。

## 安装条件

- Mac、Xcode、iOS 18 或更新版本的 iPhone，以及与该 iPhone 配对、运行 watchOS 11 或更新版本的 Apple Watch。
- 在 Xcode 中登录自己的 Apple 账号。免费账号可使用 **Personal Team** 在自己的设备上安装测试，不需要 App Store 或 TestFlight。免费签名通常 7 天到期，届时需重新构建安装。
- 安装与设备授权需要本人在 Mac、iPhone 和 Apple Watch 上操作；不要把 Apple 账号密码交给 AI 或仓库作者。

## 构建与真机安装

1. 在 Xcode 的 **Settings → Accounts** 中登录自己的 Apple 账号。
2. 在本地副本的 `ios/project.yml` 中，将 `RIYI_IOS_BUNDLE_ID` 改为自己账号下唯一的 iPhone Bundle ID，并将共用的 `DEVELOPMENT_TEAM` 填为**同一个** Personal Team ID。Watch 的 Bundle ID 和 `WKCompanionAppBundleIdentifier` 会随 iPhone ID 自动匹配。安装 XcodeGen 后在 `ios/` 目录执行 `xcodegen generate`，再打开 `ios/AiHealth.xcodeproj`。
3. 在 Xcode 的 Signing & Capabilities 中确认 `AiHealth` 与 `AiHealthWatch` 显示同一 Team，均使用自动开发签名，并保留两端的 HealthKit 权限。两端 App ID 不同，因此各自需要匹配的描述文件；**同一个 Team / 开发签名不等于共用一份描述文件**。先选择 iPhone 模拟器确认能编译。
4. 将配对 iPhone 连接 Mac，在 Xcode Device Hub 中确认 **iPhone 和 Apple Watch 均已被发现并登记**；按两台设备的提示完成信任与开发者模式。若手表未出现，先解决配对问题，不要用只含 iPhone 的描述文件给 Watch 签名。
5. 选择 `AiHealth` scheme 和配对 iPhone，构建并安装手机 App；再选择 `AiHealthWatch` scheme 和真实 Apple Watch，构建并安装手表 App。检查两份签名产物的 Team ID 与开发证书指纹一致，同时分别检查手机、手表描述文件覆盖对应的 Bundle ID 和设备。若 Xcode 已随手机 App 自动安装 Watch App，仍需在手表端确认它存在并能启动。
6. 分别在 iPhone 和 Apple Watch 上启动「日益」，确认手机端能使用本地记录、两端能完成一次演示训练同步。若要验证真实心率采集，请本人在 Watch 上授权健康权限后再单独测试。

正式客户端固定连接 `https://health.gzqy.xyz`，登录页不提供服务器地址切换或新的本地体验入口。已有账号选择「已有账号？登录」；没有账号可注册；忘记密码可通过邮件验证码找回。旧 `health.qyos.top` 由服务器兼容转发，更新时保留原账号的本机记录空间。Apple 健康读取、健康上传和 AI 分析分别由本人在 App 中授权。请勿使用仓库作者的账号或密钥。客户端仓库不需要在你的电脑上部署数据库或后端。

当前客户端构建号为 **60**。训练页按日历日期查看计划与历史，同一天可按顺序安排多个独立项目，例如力量后游泳；新增项目不会覆盖原安排。已完成实际训练但还没有日历计划的日期，也能由用户补排计划；能明确匹配的实际训练合并显示在该计划下。手动编辑周期和 AI 健康安排均支持同日多项目。计划编辑先选运动大类；力量动作从动作库选，组合直接关联已选动作，计划容量按正式组重量与次数自动计算；其他运动按时间、距离和大卡目标安排。手表可左右切换当天项目，训练可在双端暂停、继续或停止保存，结束后可重新开始。日益 App 的实际训练可在本人授权后写回 Apple 健康。默认服务器为 **56** 号 API；此公开仓库仅含客户端。

HIIT 已单列为运动大类；教练设置可保存每次动作数与每动作组数。饮食「拍照」先进入外食记录页，再选择拍照或从相册选。公开可搜索商品支持举报、屏蔽分享来源与解除屏蔽；举报商品待人工复核时暂不显示。

喝水通知正文会打开饮食里的饮水记录，不自动填写饮水量；通知的快捷操作可直接记录 250/500 ml。内测 Debug 构建的教练对话和饮食问答可并发比较 A（日益当前方案）与 B（完整 Skill 参考）；B 不提供计划导入。公开 Release 构建只显示 A。

「我的 → 数据」可查看公开隐私政策；忘记密码或无法删除账号时可从登录页、删除页进入支持渠道。

首页「最近体重」「昨日静息心率」「昨日 HRV」均可进入历史详情，查看单一来源的 7 天、30 天、90 天或 1 年趋势及逐次测量；HRV 曲线按日中位数绘制。历史优先读取本机已保存记录，再补云端，不因打开页面扫描全部 HealthKit 数据。

已练记录有独立训练总结与分享预览页，有采样时显示心率；Apple 健康若确实记录了对应训练的活动能量才显示千卡。分享图片在本机生成，缺失的重量、心率或热量不会补算。手表完成全部组后显示“完成训练”，休息结束的声音提醒需在手表允许日益通知。

团队训练分按实际完成量累计：力量计有效正式组、次数与记录的负重容量，游泳、HIIT 等计实际运动时间与合理的实际距离；同日多场可累加，单场及单日设上限。本人可在团队页查看逐场得分依据。

饮食页依次显示日历、饮水、录入入口、实际摄入和当天记录；饮水详情只显示日历选中日期的合计和记录，快捷按钮采用浅色底与深色文字。AI 粗估按上下限平均值计入“约”热量，每笔原范围仍可在记录行查看，真正缺失的热量不按零计算。

Apple Fitness 等外部 App 写入的近 7 天 HealthKit Workout，会在授权读取后生成日益的已完成训练记录。HIIT 按运动时长记录，保留原始 HealthKit UUID、来源及可用的活动能量；日益自己写入的 Workout 不重复导入。详见 [Apple 健康训练导入](docs/healthkit-workout-import.md)。

拍包装后保存会自动完成默认共享并返回常用列表。常用商品可以编辑营养表中的热量、蛋白质、脂肪和碳水化合物；修订会更新同一分享码的公开资料。其他账号导入的是独立副本，可主动检查来源更新；已吃记录保留当时的数值。文字和外食照片的营养素为 AI 粗估范围，份量变化后不沿用旧估算。饮食页展示热量、蛋白质、脂肪、碳水四项进度；健康档案可逐项手填目标，留空则在资料足够时自动计算，规则见 [蛋白质与营养记录](docs/protein-and-macros.md)。教练对话只显示一份完整 Skill 参考的回复，发送前会先同步待上传的饮食记录，旧 A/B 对照不再触发。

换用自己的 Bundle ID 会创建独立的 App 数据空间，不会自动迁移其他安装版的本地记录。测试时不要卸载已有的同名 App，先确认 Bundle ID 与数据空间。
